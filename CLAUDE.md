# Project rules for Claude

Terraform automation for Palo Alto Networks Strata Cloud Manager (SCM), using the
`PaloAltoNetworks/scm` provider. These rules are owned by the repo owner — edit freely.
Hard limits are also enforced in `.claude/settings.json`.

## Claude CAN (without asking)
- Read, write and refactor Terraform, Python scripts and docs in this repo.
- Run read-only commands: `terraform fmt`, `init`, `validate`, `plan`, `show`, `output`,
  `providers`, `python scripts/scm_auth_check.py`, and `scripts/scm_devices.py`, `scripts/scm_onboarding_rules.py` and `scripts/scm_virtual_routers.py` without `--apply`.
- Install the Python packages listed in `requirements.txt` into `.venv` (add new ones there).
- Make read-only (GET) calls to the SCM API.
- Commit to git and push to `origin` (github.com/bgalhoufa/panw_scm).

## Claude must ASK first
- `terraform apply`, `import`, `state rm|mv`, `taint`, `force-unlock` — always show the
  plan summary (adds / changes / destroys) and wait for explicit "yes".
- Any non-GET call to the SCM API (POST / PUT / DELETE).
- Adding new Terraform providers or modules from the registry.
- `scripts/scm_devices.py --apply` (moves firewalls between folders); show the dry-run output first.
- `scripts/scm_onboarding_rules.py --apply` (creates/updates onboarding rules); show the dry run first.
- `scripts/scm_virtual_routers.py --apply` (creates/updates virtual routers); show the dry run first.
- `scripts/fw_ssh_baseline.py --apply` (SSH to firewalls: factory-default virtual wire cleanup, hostname, SNMPv3, local superadmins, commit); show the dry run first.
- Creating GitHub Actions workflows or anything that runs automatically.

## Claude must NEVER
- Run `terraform destroy` or `terraform apply -destroy`. Undo is done only through
  `scripts/deployments.py restore` + a reviewed plan (see the `scm-change` skill), and never
  removes a managed root that still contains firewalls.
- Push / commit the SCM candidate configuration to devices or Prisma Access
  ("Push Config" / jobs API). The repo owner does this manually in SCM.
- Touch folders other than the ones listed under "Scope" below.
- Print, log, commit or paste secrets (`.env`, client secret, tokens, `*.tfvars`, state files).
- Modify or delete objects in SCM that are not managed by this Terraform code.
- Force-push or rewrite git history on `main`.

## Scope (SCM folders Claude may manage)
- The managed roots listed in `scripts/scope.py` (`MANAGED_ROOTS`) and every folder below them.
  Today: `SITES-1XX`, `SITES-2XX`, `SITES-3XX` (site types, directly under All Firewalls) and `PANW` (lab folders only, until
  the lab firewalls move out). New roots (e.g. mixed `SITES-1XX-3XX`) only on the owner's request.
- All Firewalls (`ngfw-shared`) itself and every other folder (HOME-LAB, BALCOES, DATACENTERS,
  FLIGHT, Prisma Access, ...) are read-only for Claude.
- Tenants: `default` = lab tenant (`.env`); `customer` = the customer's tenant (`.env.customer`). PANW exists only in
  the lab tenant. In the customer tenant its existing folders (RAGRA, "RAGRA e RAAI", ...), snippets ("GRA - RAAI",
  "GRA - RAGRA", "GRA_device_config", ...) and firewalls outside SITES-* are read-only; moving a firewall out of
  them needs the owner's explicit approval (`--allow-out-of-scope-source`).

## Conventions
- Credentials come only from environment variables / `.env` (see `.env.example`); a second tenant's SCM_*
  credentials live in `.env.<tenant>` (git-ignored). Load them in PowerShell with `. .\scripts\load-env.ps1`
  (lab) or `. .\scripts\load-env.ps1 -Tenant customer`; Python scripts pick the tenant from `SCM_TENANT`.
- One Terraform workspace (local state) per tenant, selected by `TF_WORKSPACE` from load-env.ps1. Generated code
  is stamped with its tenant (`SCM_TENANT` when running `workbook_to_tf.py`); `terraform/tenant.tf` stops the plan
  if credentials, workspace and generated code disagree. Before planning a tenant, regenerate `gen_*.tf` from
  that tenant's workbook. Deployment tags: `deploy/<ts>-<name>` (lab), `deploy/<tenant>/<ts>-<name>` (others).
- Invoke Terraform as `terraform ...` from the `terraform/` directory (not via a full
  path) so the permission rules in `.claude/settings.json` match.
- Follow the `scm-change` skill for any change that will reach SCM.
- `terraform/gen_*.tf` is generated by `scripts/workbook_to_tf.py`; never edit it by hand.
  Each applied deployment is tagged `deploy/...` by `scripts/deployments.py record`.
- Bulk input arrives as a filled copy of `templates/SCM_bulk_template.xlsx`. Read it with
  `scripts/template_io.py`; never commit a filled-in workbook unless the owner asks.
- Use ONE cumulative workbook for the whole rollout (waves add rows). The converter rebuilds all
  `gen_*.tf` from the file it gets, so a per-wave file would plan to delete earlier waves.
- Python scripts run from `.venv` (`.venv\Scripts\python`).
- Terraform state stays local on the owner's PC (owner's decision): no remote backend. This repo
  is the tooling for a ~200-firewall rollout; after it, Terraform is retired and SCM is managed
  directly, so never design anything that needs `terraform destroy` or long-term state.
- Per-firewall values are variables with `device = <serial>`; firewalls roll out in waves
  (`wave` column, `scm_devices.py --wave N`).
- Folder design (owner's decision, 2026-11-19): one top-level folder per site type (`SITES-1XX`, `SITES-2XX`, `SITES-3XX`
  sites) holding everything shared by that type (interface variables $wan1/$wan2/$lan/$lan.<VLAN>, zones,
  logical routers, DHCP relays, device settings, variables with placeholders); one folder per site below it
  (`SITE003`, ...) holding only its variable values and local DHCP. Each firewall is placed in its site
  folder; one firewall per site. Branch types / entities are labels, not folders. Hostname, SNMPv3 and
  local superadmins are set over SSH by `scripts/fw_ssh_baseline.py` (no SCM API for them). Run it before the
  first SCM push: it also removes the factory-default virtual wire (ethernet1/1 + 1/2), whose local definitions
  override SCM's layer 3 interfaces and make the push fail.
- SCM scope rule: a reference resolves only inside the same snippet, or in the same folder and the
  folders above it. Snippets must be self-contained. In folders/snippets interfaces must be interface
  variables (`$name` + `default_value` = physical port). `validate_workbook.py` enforces both.
- Routing (owner's decision, 2026-11-19): PA-410 allows only one logical router, so sites use legacy virtual routers
  (VR-RAGRA, VR-IoT) and the firewall runs in legacy routing mode (advanced routing off). Terraform has no virtual
  router resource: the Virtual Routers sheet + their Routes are applied by `scripts/scm_virtual_routers.py` after
  `terraform apply` (it never deletes a router). Logical Routers stay supported for other models.
- When the template gains sheets / columns, move filled workbooks over with `scripts/upgrade_workbook.py <file>`.
- The cumulative workbook per tenant: `inputs/rollout.xlsx` (lab), `inputs/rollout-customer.xlsx` (customer).
- Before automating anything, check `docs/api/SCM_API_ENDPOINTS.md`: prefer Terraform when the
  endpoint has a `scm_*` resource; if it is API-only, propose a script and ask first; if it is not
  listed, the API cannot do it.
